The manuscript baseline is the user-named `first-isac-paper/clutter_aware_beamforming.pdf`. It is byte-identical to `first-isac-paper/manuscript/main.pdf`, SHA-256 `18b94f44fd1a3a69c8033fb127400d67527d56f7ff25909bb1679c4396e3bad9`. ## Equation and implementation cross-check

The MATLAB Monte Carlo driver inlines the fast solver. Its local functions and the matching standalone pilot share the conventions described below. The Python budget run is the physics-only counterpart and uses no policy weights.

| Manuscript equations | Implementation and deviations |
| --- | --- |
| (4)–(6), steering, target return and gain | `configure`, `load_case` and `fig12b_SCNR_Gamma.m` agree on unit-norm, frequency-dependent ULA steering and the fixed target coefficient including P. The physical replay uses second moments. The instantaneous echo in (5) and its delay/Doppler phase are not simulated in the solver. P multiplies both the target coefficient and the covariance budget under this convention. |
| (7)–(8), cold-clutter kernel | Tutorial `kernel_apply.m` and Python `Kernels.apply` use column-major vectorization and Hermitian symmetrization. Users of the fast solver load the precomputed MAT file. The upstream generator implements (8) as weighted outer products of vectorized Rx/Tx steering covariances, including designated nuisance/UAV terms. It uses a Choi PSD projection and its documented eigenvalue load for the estimated kernel, and uses target-free hot-plus-noise samples for the fixed additive covariance. |
| (13)–(15), receive update and d0 | Both fast paths and the paper's AO driver use an unloaded MVDR linear solve and distortionless normalization. The tutorial function has a ridge default when its caller omits it. In AO the common target/clutter/additive scale is `1e-8/(d0/N)` for positive d0, or one if d0/N is nonpositive. In the LP the Charnes–Cooper denominator is normalized by d0. Python divides directly and MATLAB explicitly checks positive d0 and reward scale. |
| (16a)–(16d), AO–SDP | The SDP drops the constant `-rho*d0` in its maximization as described in the manuscript. The ratio update includes the scaled d0. The solver rescales communication channels by `sqrt(1e10)` and communication noise by `1e10`. It requests MOSEK with `cvx_precision high`. The code uses `RX - sumR == semidefinite(Nt)`, which constrains the residual to a **real symmetric** PSD matrix while (16c) allows a complex Hermitian PSD residual. The code's cone is a substantive restriction. The observed effect on scores remains unmeasured. [CVX function reference](https://cvxr.com/cvx/doc/funcref.html) |
| (16), AO stopping and scoring | Fig. 12(b) and the named manuscript driver set 30 outer and 30 Dinkelbach iterations, 0.01 dB absolute outer-change threshold (strict less-than), and 0.001 relative inner threshold (less-than or equal). The inner relative test places a `1e-30` floor under the old ratio's magnitude. AO seeds normalized Gaussian transmit covariance, which need not meet QoS. AO returns the post-transmit covariance and the receiver computed before that transmit step. The fast path refreshes the receiver after its final accepted transmit update. The tutorial figure uses the AO returned covariance and receiver. The named manuscript scores the recovered AO streams with that same returned receiver. |
| (17), stream recovery | Tutorial user recovery floors a nonpositive desired covariance quadratic form at `1e-12`. The LP form computes `Vk*(response/norm(response))` using weighted atom columns and leaves zero if the norm is zero. Scaling the channel by its positive norm cancels in this formula. All paths Hermitianize the residual, keep the top Ns−K eigenmodes and clip negative retained eigenvalues to zero. The code has no omitted-rank or omitted-mass logging in these paths. |
| (19)–(22), ZF and bank | The 3K+2 initial atoms per tone and their ownership agree. Both LPs multiply gamma by `1+2e-5` in the start and in the master. The achieved SINR is audited against nominal gamma. The MATLAB seed falls back to a null-space basis at projected target norm below `1e-10`; Python normalizes the projected target directly. Both reject a start whose ZF user beams consume the full budget or more. |
| (21)–(23), Charnes–Cooper master | Both use `Ps=P*(1-1e-8)`, rescale QoS rows by `d^(-1/2)` and unscale their duals. They hard-clip **all** negative LP clutter coefficients to zero with no roundoff test. Pricing uses the unclipped matrix C. The MATLAB code clamps negative primal powers to zero at decode and checks t>0. Python clamps powers inside recovery and relies on solver success and the formulation for t. Python HiGHS sets primal and dual feasibility tolerances to `1e-9`. MATLAB first probes `linprog` with constraint/optimality tolerances of `1e-9`, then can fall back to defaults or CVX. CVX fallback inherits its configured backend/precision and accepts status text containing `Solved`. The archived backend and actual historical residuals are unavailable. |
| (24)–(25) and following certificate | Both use a Hermitian principal eigenvector, add per owner for reduced cost above `1e-7` and accumulate the maximum positive excess. The code uses the optimal **scaled primal** value as the exact-arithmetic proxy for the equality dual. The theorem assumes positive psi and consistent PSD clutter coefficients. MATLAB floors the divisor at machine eps and Python at `1e-16`. Neither baseline records primal–dual discrepancy, eigenvalue residuals or the size of clipped coefficients. A pass prices after every master, including after the terminal LP; newly appended terminal columns can go unused. |
| Following (25), acceptance and stopping | The comparison is on recovered W and the fixed estimated-kernel receiver. The gate is nominal SINR margin ≥ −1e−4 dB, physical power ≤ `P*(1+1e-7)` and fixed-receiver score ≥ `best*(1-1e-10)`. The stop is bound ≤ 0.002 dB in the inner loop and both bound ≤ 0.002 dB and **signed** outer gain < 0.002 dB in the outer loop. Thus a slight decrease accepted within tolerance also passes the gain test. These budgets are caps. |
| (26)–(30), policy | MATLAB uses a shared 4→6→4 transmit MLP, the target/clutter and normalized user-gradient terms, and only the nonzero user proposal columns. Numerical guards use `realmin` for the feature, gradient and step denominators. Its inference baseline reads the step from `model.fixed`. The Python pilot's `angles` supports the same parameter layout, uses a default step of 0.6 and omits several MATLAB denominator guards. That Python helper is not called by the 32-channel held-out run. The MATLAB SPSA W rollout optimizes terminal log estimated SCNR through anchor repair (23 bisection steps). The later U-training stage freezes W. |

Part 0 preserves the baseline solver implementations. Exact solver and thread matching across MATLAB and Python will require explicitly configured stacks and logged residuals in subsequent parts.

## Source-level leads for Part A

- The tutorial Fig. 12(b) script uses 100 trials per K/SINR setting, K values 4, 8 and 12, and `rng('shuffle')` before a `parfor`. At the two target thresholds it uses the same nominal P, target coefficient convention, distance range, path-loss exponent and AO options as the manuscript driver. Its estimated-kernel points use the ideal kernel and returned covariance for scoring, and aggregate finite positive scores in linear units before conversion to dB. The paper's MATLAB experiment uses fixed channel seeds, recovered streams, a physical feasibility audit and paired dB statistics.
- The bundled `covMat_BLP.mat` has metadata L=512 and Pt≈199.526 W, matching the separate calibration generator configuration. Fig. 12(b) overrides L to 64 and Pt to 100 W while keeping the distributed matrices. The AO/LP second-moment routines do not read L. Changing only the L field after loading the file does not modify their inputs. A calibration-L contrast requires matched regenerated kernels with the same calibration inputs and independent provenance for each kernel.
- The arXiv tutorial text describes L=32 secondary snapshots with 64-QAM probing. The pinned generator configures L=512 and 4-QAM. The named script configures L=64 for design. These are three distinct records, and the manuscript must preserve the distinction between data-generation settings and the design parameter field. Whether the distributed data and published figure came from identical conditions is unresolved. [Liu et al., Fig. 12 discussion](https://arxiv.org/abs/2602.10537v2)
- The original real-symmetric residual constraint is part of the pinned baseline. The complex Hermitian cone in the manuscript is a candidate single-factor reconciliation arm if the author approves. No benchmark gap or fresh speedup has been estimated.

## Environment and artifacts

The fresh replay used Debian 13, Linux 6.18.57, Intel Xeon Platinum 8573C, three logical CPUs visible with a two-CPU cgroup quota, an 8 GiB memory limit and CPU-only execution. It used CPython 3.12.14, NumPy 2.3.5, SciPy 1.17.0, SciPy-bundled HiGHS 1.8.0 (`222cce7`), threadpoolctl 3.6.0 and Matplotlib 3.10.8. Both loaded OpenBLAS 0.3.30 libraries were limited to one BLAS thread. The solver's native thread option remained automatic and the child process reported one or two OS threads during sampling. The archive's term “single numerical thread” is verified for the BLAS guard only. The historical MATLAB runtime, CVX, MOSEK, LP backend, thread counts and exact hardware are unresolved.

## Part D terminal LP feasibility discrepancy

The Part D replay found two terminal 5×3 B8 allocations with decoded QoS row shortfalls relative to normalized noise of 1.93 and 1.11 despite zero solver-reported inequality residuals. The seed and operating conditions are 10005 (six users, 8 dB) and 10020 (four users, 12 dB). The originally returned stream designs passed the physical gate. The independent HiGHS interior-point re-solves verified both restricted objective values on the exact same receive filters and dictionaries to within the registered numerical tolerance. The reported LP atom-use statistics describe the original solver allocations. See `PART_D.md` and `results/partd-2026-11-22/` for the feasibility witness, rechecks and the distinction between the LP objective and decoded allocation. Any production solver change and associated retiming requires a separate comparison.
